# 商城功能扩展（2026-10-10）

本轮在已有 Angular + Spring Boot MVC 项目中完成九项需求，保留原有账号、收货地址、订单快照与中英文功能。源码、`src/main/resources/static/products` 和 `runtime/shopping-cart.jar` 已同步构建。

## 功能与操作

| 需求 | 实现 |
| --- | --- |
| 总览加购和数量调整 | 加购图标变为减号、数量输入框、加号；支持直接输入数量，设为 0 或减到 0 后恢复图标。数量与导航购物车徽标由服务器同步，刷新后仍可调整。 |
| 突出 View details | 商品卡片底部使用较大字号、整行浅绿色按钮，并保留独立图片放大入口。 |
| 评价、星级、销量与排序 | 总览和详情显示平均星级、评价数、已售件数。移除 Newest，增加 Best selling 和 Top rated；价格与名称排序保留。 |
| 购买后评价 | 匿名用户看到登录提示；登录但未购买时看到购买要求。后端同时检查当前 Session 身份与本人该商品的已完成订单，不能通过伪造请求绕过。每人每商品一条评价，重复提交更新原评价。 |
| 导航一致与高亮 | 首页、购物车、订单、账户、管理后台使用一致的中英文名称；当前栏目带高亮和 `aria-current`。地址管理归属账户，结账归属购物车，成功页归属订单。 |
| 首页结构与推荐 | 导航下方先搜索；大横幅可切换 Keycraft 品牌广告与桌面焕新活动，链接到相关商品。每日推荐结合浏览品类、购买记录及较高评分品类；新访客显示每日变化的热门精选。 |
| 管理后台 | `/admin/products` 支持新增、编辑、删除、上下架、库存数量及缺货自动隐藏。补货后自动显示；手动下架的商品仍需手动上架。已被订单或评价引用的商品保留历史数据，可下架。 |
| Service Layer | Controller 接收请求与组织页面，Service 执行购物车、购买资格、推荐、支付与库存规则，Repository 负责数据库访问。新增 `RecommendationService`、`PaymentService`，扩展已有商品、评价、结账服务。 |
| 模拟支付 | 结账可选择模拟银行卡网关或数字钱包，并选择成功/失败结果。成功保存支付状态、方式、流水号、时间；失败保留购物车且不生成订单、不扣库存、不增加销量。订单详情和成功页都有支付凭证。 |

## 数据与一致性

- 新增库存字段默认为 100 件，兼容原有商品表；管理员可改为 0–1,000,000。购物车每商品最多 99 件，同时受实际库存限制。
- 支付、库存扣减、订单和订单明细在同一数据库事务中完成。商品按 ID 顺序加行锁，防止两个会话购买同一件剩余库存；同一结账令牌有唯一约束，重复提交不会重复扣库存。
- 平均星级与评价数从评价表计算，销量从已完成订单明细的数量求和，不使用前端硬编码数字。订单支付状态为空的旧订单视为升级前已完成订单，不伪造支付流水号。
- 首次升级为现有示例目录补充三位示例顾客的历史购买和评价：新库 40 个商品各三条，共 120 条示例评价。页面明确标注“示例评价”。示例销量来自这些购买明细，和之后的模拟购买共同参与销量计算；它们不是实际商业销售数据。
- 示例记录使用单独的随机账号和随机密码，不占用 alice、bob 或管理员账号，不修改这些账号已有的订单、密码和评价。历史示例购买不扣减当前期初库存。初始化版本记录保证重启不重复添加。
- 推荐使用当前会话浏览记录和已登录账号历史；先筛选，再推荐排序和分页。同一天同一偏好排序稳定，搜索、分类与显式价格/销量/评分排序继续可用。当前小规模目录在服务层完成推荐排序。
- 广告使用目录中已有 Keycraft 品牌和桌面活动作为演示。它们在 Angular 首页模板中维护，本轮后台范围为商品管理。

## 运行与演示

在含 `pom.xml` 的内层 Group2 目录执行：

```powershell
java -jar runtime/shopping-cart.jar --spring.profiles.active=b-demo
```

默认演示地址：`http://127.0.0.1:18083/products`。如果已有旧演示占用端口，先停止旧进程，或附加 `--server.port=18085` 使用另一端口。

普通账号：`alice / demo123`、`bob / demo123`；演示管理员：`admin / admin123`。演示使用 H2 内存数据库，停止后数据丢失。正式 MySQL 的连接与管理员设置沿用 README。

建议演示顺序：

1. 查看首页搜索、广告切换、每日推荐和销量/评级排序。
2. 登录普通账号，在总览加购、加减数量、输入 0、刷新页面。
3. 打开未购买商品详情，确认评价区显示购买要求。
4. 进入购物车和结账，添加本人收货地址。选择支付失败，确认购物车保留；再选择支付成功，查看交易流水号。
5. 回到购买商品，提交或修改评价，检查详情和总览上的评分及销量。
6. 登录管理员，新增商品、修改库存、开启缺货自动隐藏，将库存设为 0 后检查前台，再补货检查恢复显示。删除未被购买/评价的测试商品。
