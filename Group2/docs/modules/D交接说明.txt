三、代码分工
entity/Order.java：订单主表，关联用户、记录总额、时间和唯一结账标识。
entity/OrderItem.java：明细表，关联订单及商品，保存成交名称、单价和数量。
repository/OrderRepository.java：按结账标识与用户 ID 查询订单。
repository/OrderItemRepository.java：按订单 ID 查询明细。
service/CheckoutTransactionService.java：在一个事务中重新核价、保存订单和明细。
service/CheckoutService.java：校验结账输入，处理重复请求及数据库唯一约束冲突。
service/CheckoutCoordinator.java：协调 Session、购物车版本和事务完成后的清空。
service/CheckoutReceiptService.java：查询当前用户的本次订单成交数据。
dto/CheckoutReceipt.java：向成功页提供订单回执与明细数据。
controller/CheckoutController.java：结账确认、提交和成功回执路由。
controller/CheckoutPageAdvice.java：处理结账页面的登录与业务错误。
CheckoutCoordinator 保留 C 作者 Letian Xie 的版本检查思路来源说明。
所有交付类已标注邱弈杰；未把 A/B/C 文件计为 D 开发内容。

四、调用过程
浏览器提交 → CheckoutController → CheckoutCoordinator → CheckoutService
→ CheckoutTransactionService → Repository → MySQL。
事务成功返回后，CheckoutCoordinator 才调用 C 的 clearCart。
任何写入失败会回滚订单和明细，购物车保留。
成功页由 CheckoutReceiptService 查询已成交的名称、价格和数量。

五、与组员对接
A：ProductService.findProductById(Long) 必须只返回存在且可售的商品。
   商品使用 BigDecimal 价格和 active 状态；成交价格不信任浏览器输入。
B：验证数据库账号成功后，在服务器 Session 保存 Long 类型 loginUserId。
C：提供 CartService.requireUserId、revision、readForCheckout、clearCart、
   getCartItems、calculateTotal、countTotalQuantity、canCheckout，
   并约定 CHECKOUT_STATE_ATTRIBUTE；退出或切换用户时清理旧会话状态。
   保留 templates/orders/checkout.html 和 checkout-success.html，
   确认表单 POST /checkout，隐藏参数名 checkoutToken。
   确认页模型：cartItems、cartTotal、totalQuantity、canCheckout、checkoutToken。
   成功页模型：receipt，其字段 id、createdAt、totalAmount、items；
   每行字段 productName、unitPrice、quantity、subtotal。
E：使用本包 Order 与 OrderItem 实体开发历史查询。必须按当前登录用户过滤。
   orders 字段：id、user_id、created_at、total_amount、checkout_token。
   order_items 字段：id、order_id、product_id、product_name_snapshot、unit_price、quantity。
   历史名称和价格使用明细快照；商品下架保留记录，避免删除被引用商品。
   新增历史查询 Repository 方法时与 D 协调合并。
