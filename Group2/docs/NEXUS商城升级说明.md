# NEXUS Digital 商城升级说明

> 本文记录前一轮版本。最新支付、评价、折扣和运行方式以 [结账与评价流程更新](NEXUS结账与评价流程更新.md) 为准。

本轮将商城定位为数码与办公用品品牌 **NEXUS Digital**，宣传语为“数码助力办公，灵感自在发生。”首页继续提供商品搜索、广告活动和每日推荐。

## 本轮 13 项调整

| 需求 | 实现与使用规则 |
| --- | --- |
| 1. 注册密码 | 8～50 个字符，必须同时包含大写字母、小写字母和特殊字符；服务器再次校验，并保留 BCrypt 的 72 字节限制。 |
| 2. 简化个人信息 | 注册和个人资料移除 Full name；保留昵称、邮箱、手机号和选填生日。收货地址仍填写收件人姓名。 |
| 3. 双语校验 | 登录、注册、资料、地址和支付提示跟随所选中英文；账号表单使用页面内提示，避免浏览器系统语言覆盖选择。 |
| 4. 多方式登录 | 登录页可切换用户名、邮箱、手机号，均使用账号密码验证；手机号允许空格、括号、连字符和国家区号。邮箱、手机号不能绑定其他账号；旧数据如有重复联系方式，仍可用用户名登录。 |
| 5. 移除演示账号提示 | 登录页不再显示 Demo account 或演示密码。 |
| 6. 统一导航 | Angular 商品页和 MVC 页面统一品牌、布局、文字、购物车数量和当前页面高亮。 |
| 7. 商品排序 | 移除名称排序；保留推荐/精选、价格、销量和评分排序，价格按优惠后的实际售价排序。 |
| 8. 销量与评价分布 | 示例商品销量分布为 5～9,600 件，每件商品有 5～120 条评价，评价数不超过销量；评分覆盖约 1.2～5.0 星，包含低分和满分情形。 |
| 9. 扩充产品矩阵 | 全新演示库包含 66 件双语商品、10 个类目；新增商品同时有销量和评价。 |
| 10. 评价入口 | 商品详情保留评价展示，移除“分享你的体验”表单；评价入口统一放在自己的订单详情中。 |
| 11. 支付模拟 | 支持 Visa、Mastercard、UnionPay、American Express 和加密货币；填写模拟支付资料后生成与选择对应的凭证。 |
| 12. 物流与收货 | 支付成功后模拟揽收、运送、派件、签收，并立即推进到“等待确认收货”；买家确认后，在原订单详情内显示评价表单，提交后原地更新。 |
| 13. 商品折扣 | 促销商品同时显示原价、突出显示的优惠价和优惠百分比；管理员可设置 0～90 的折扣优惠百分比，0 表示不促销。 |

10 个类目：电脑与配件、键盘与鼠标、桌面好物、音频设备、显示器与屏幕、存储设备、充电与电源、网络设备、打印与扫描、手机与平板。

## 运行与演示

在包含 `pom.xml` 的项目目录运行本轮构建后的 JAR：

```powershell
java -jar runtime/shopping-cart.jar --spring.profiles.active=b-demo --server.port=18086 --server.address=127.0.0.1
```

- 商城：<http://127.0.0.1:18086/products>
- 后台：<http://127.0.0.1:18086/admin/products>
- 演示管理员：`admin` / `admin123`。
- 演示普通账号：`alice` / `demo123`、`bob` / `demo123`。新注册密码须遵守新的强度规则。

此命令使用独立 H2 内存库，停止进程后演示订单、资料和后台改动会清除。默认 MySQL 运行方式仍见 README；本轮验证结果不代表已验证现有 MySQL 数据库。正式 MySQL 配置不会自动创建演示管理员。

建议按以下流程检查：

1. 切换中英文，注册新账号；测试弱密码、无效邮箱，再用有效资料完成注册。依次测试用户名、邮箱和手机号登录。
2. 浏览不同类目，按销量、评分和价格排序；检查高低评分、促销价格、购物车数量调整及导航一致性。
3. 加购商品、保存收货地址，在结账页选择支付方式并点击“填入示例资料”。可以先选择拒绝支付，确认购物车保留，再选择成功支付。
4. 打开订单详情，检查支付凭证、物流时间线和等待确认收货状态；确认收货后，在同一页面填写星级和评价。
5. 使用管理员账号编辑商品，将折扣设为 25，确认前台显示原价的 75%；设为 0 后恢复原价。也可调整库存、上下架和缺货自动隐藏。

## 支付与凭证

银行卡表单校验卡组织、卡号校验位、持卡人姓名、有效期、安全码和 6 位模拟支付密码。页面提供各卡组织的示例填充按钮；例如 Visa 可使用 `4242 4242 4242 4242`、未来有效期、安全码 `123` 和模拟密码 `123456`，运通安全码为 4 位。

加密货币支持 BTC/Bitcoin、ETH/Ethereum、USDT/Ethereum 或 Tron，页面可填入对应的模拟钱包地址。换算采用固定演示报价，不连接交易所或链上网络。所有支付均为本地模拟，不发生真实扣款。

凭证保存支付方式、交易编号、时间和卡号末四位；加密货币凭证保存币种、网络、模拟金额和钱包末六位。完整卡号、安全码和支付密码不落库、不回显；失败支付不生成订单、不扣库存。

## 数据与服务层

- `Product.price` / `originalPrice` 表示原价，`discountPercent` 表示优惠百分比，`effectivePrice` 表示实际售价：`原价 × (100 - 优惠百分比) / 100`，四舍五入到分且不低于 S$0.01。购物车、价格排序与结账使用实际售价，订单保留下单时的价格快照。
- `CatalogSeedProducts`、`DataInitializer` 管理商品矩阵；`ReviewSampleInitializer` 生成带 **Sample review / 示例评价** 标识的评价，以及对应的已确认收货示例购买。初始化有版本记录，示例历史销量不扣减当前库存，升级仅替换明确标记的旧模拟购买和评价。
- MVC Controller 负责请求、表单和页面；`AuthService` 负责账号及登录方式，`ProductService` / `RecommendationService` 负责商品查询和推荐，`AdminProductService` 负责后台商品及折扣校验。
- `CheckoutCoordinator` / `CheckoutTransactionService` 负责结账幂等、库存锁与订单事务；`PaymentService` 校验模拟支付并生成安全凭证；`OrderCompletionService` / `ProductReviewService` 在服务层检查订单归属、确认收货状态和评价权限。
- 评价需要属于当前账号的已确认收货购买记录。页面隐藏表单之外，服务层同样拒绝未登录、未购买或尚未确认收货的请求。
