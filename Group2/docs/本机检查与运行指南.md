## 检查结论

实际工程根目录是外层 Group2 下面的内层 Group2，即包含 pom.xml 的目录。老师 PDF 的五项核心功能在工程中均有实现：商品浏览、登录退出、购物车、结账、购买历史。项目使用 Spring Boot MVC、MySQL 配置、JPA、服务端表单校验；Angular 商品页通过 REST 获取数据，满足至少一项功能使用 Angular/React + REST 的要求。

现有额外功能包括服务层、商品和订单分页、注册与资料管理、商品后台与上下架。模拟支付、评价、库存不是必做项；不需要临近提交再大幅扩展功能。

### 已确认并修复的问题

1. **非法分页参数和不存在的页面返回 500**：全局异常处理的兜底捕获了 Spring MVC 已明确表示 400/404 的异常。现在非法页码/每页数量返回 400，缺失页面和静态文件返回 404，相关 REST 错误返回 JSON。改动位于 GlobalExceptionHandler，新建 HttpErrorHandlingTest。
2. **购买历史跨页重复**：原 SQL 仅按下单时间排序，时间相同时顺序不稳定。改为时间倒序、订单 ID 倒序；现有分页测试增加了七笔订单时间完全相同的条件，断言两页完整且不重复。改动位于 OrderQueryRepository 与 PurchaseHistoryServiceTest。
3. **新增商品取消“Visible in the store”仍然上架**：原 Controller 未传递 active，Service 固定写 true。现在新增时在同一事务保存用户选择，旧的四参数 create 方法仍默认上架。新增页面级回归测试。改动位于 AdminProductController、AdminProductService、ModuleEWebTest。

## 正式运行：使用你的 MySQL

本机 MySQL80 服务已安装并运行，无需再装另一个数据库服务器。

1. 打开 MySQL Workbench，用你自己已有的连接登录。
2. 在 SQL 编辑器执行 database/create-database.sql：

   ```sql
   CREATE DATABASE IF NOT EXISTS shopping_cart
     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

   如果已存在同名数据库，先确认它就是这个项目的数据库；JPA update 会修改其中实体对应的表。
3. 双击 **Start-MySQL.cmd**，在本机输入 MySQL 用户名与密码。密码不回显，脚本不会保存密码文件。
4. 看到启动成功后打开 http://127.0.0.1:18080/products 。此入口强制使用 MySQL，避免继承临时演示 profile。
5. 首次空库会初始化 12 件商品与 alice、bob。已有账号密码不会重置；正式库不会自动建立 admin。
6. 正式管理员按 README 的步骤注册专用账号，再在数据库将其角色改为 ADMIN，重新登录。

自定义数据库和端口时，在内层 Group2 的 PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Local.ps1 -Mode MySQL -DatabaseUrl 'jdbc:mysql://127.0.0.1:3306/shopping_cart' -Port 18080
```

常见报错：`Access denied` 表示数据库账号/密码或授权问题；`Unknown database` 表示尚未建库；`Communications link failure` 通常应检查 MySQL 服务、主机和端口；端口占用则停止此前的同端口程序或指定其他端口。

MySQL 验收建议：alice 下单后停止并重启程序，确认历史仍在；bob 不能查看 alice 的订单；管理员改价和下架不能改变历史成交金额。录制演示时建议使用这种模式。

## 修改代码后重建

本次补齐了项目内便携 Node.js 24.19.0，位于 .local/tools/node-v24.19.0-win-x64，未写入系统 PATH。官方发布与下载：<https://nodejs.org/en/blog/release/v24.19.0>。其 ZIP 已校验官方 SHA256。

仅查看网站或改后端时不需要 Node。修改前端时可双击 **Start-Frontend.cmd**，该脚本优先使用本项目内 Node，启动 http://127.0.0.1:4200/ 。开发代理默认指向 18080，因此同时运行正式后端；若使用 b-demo，把 frontend/proxy.conf.json 的目标改成 18083。浏览器两端统一使用 127.0.0.1，避免 Session Cookie 因主机名不同而丢失。

完整重建，在内层 Group2 的 PowerShell 执行：

```powershell
$env:Path = (Join-Path (Get-Location) '.local\tools\node-v24.19.0-win-x64') + ';' + $env:Path
cd frontend
npm ci
npm run deploy
cd ..
.\mvnw.cmd clean package
```

Java 测试和依赖安装首次可能需要联网。此电脑的 Codex 受限进程使用了 .local/maven-settings.xml、工作区 TEMP 和 Mockito javaagent；这些是检查环境适配，不是作业的业务配置，普通用户终端先运行正常命令即可。

启动脚本会优先选修改时间更新的可执行 JAR。若你从源码重新打包，通常选 target 下的新 JAR；提交时还应把新 JAR 复制到 runtime，以免别人运行旧交付。
