# 商城功能与体验升级

本轮保持 Angular 商品前端、Java Spring Boot MVC/REST、Thymeleaf 和 JPA/MySQL 架构。界面统一为 Everyday Market。

## 新增与调整

- 首页重新设计为介绍区、四大分类入口、搜索排序工具栏和商品目录。分类支持电脑与配件、键盘与鼠标、桌面办公、音频设备，首次升级初始化每类 10 件商品。
- 点击商品图片打开放大预览，支持关闭按钮、背景点击、Escape 和焦点恢复；“查看详情”进入商品详情；购物车图标一键加购，保留当前页面并更新购物车数量。
- 分类、关键词、排序和页码保存在 URL 中；详情返回目录保留筛选，“继续购物”恢复本次浏览的目录位置。
- 商品具有品牌、发货地、分类、中英文名称与介绍。管理员可维护这些字段。示例品牌和商品仅用于课程演示；没有伪造用户评价。
- 商品详情显示真实用户评价和平均评分。登录用户可发表或修改自己的评价，每位用户每个商品一条，内容保存到数据库。
- 注册补充真实姓名、联系电话和可选生日。账户页展示并编辑姓名、显示名称、邮箱、电话、生日，修改保存至 `app_users`，下次登录重新读取数据库。
- 地址管理支持新增、编辑、删除和设置默认地址，每个账户最多 20 个地址；收件人、电话、国家、城市、邮编、街道为必填，楼栋/单元可选。
- 结账必须选择当前用户的收货地址。没有地址时引导添加，并能直接回到结账。订单保存收件人、电话与地址快照，后来修改或删除地址不会改变旧订单。
- 顶部一键切换中英文。Angular 与 Spring MVC 共同读取 `store_lang` Cookie，跨页面保持语言；Thymeleaf 使用 Spring MessageSource 消息文件。
- 统一品牌、导航、页脚、错误页与页面样式；移除重复加购入口和无功能的分类文字；分页边界不再提供可误点的链接。

## 数据与安全边界

新增 `shipping_addresses`、`product_reviews`、`catalog_seed_versions` 表，以及用户、商品、订单上的新增字段。正式 MySQL 继续使用现有 `ddl-auto=update`。旧订单可以没有地址快照，详情会明确显示说明。

目录初始化使用一次性版本记录：保留已有账号密码和商品名称、价格、描述、图片、上下架状态；升级补充缺失的分类信息与示例商品。后续启动不会重新创建已删除商品或重新上架已隐藏商品。

地址查询和写入均限制当前登录用户，资料编辑不接受用户 ID 或角色。资料和地址写操作验证会话令牌；加购及评价验证购物车会话令牌。结账保留服务器重新核价、事务回滚和唯一令牌防重复机制。

被订单或评价引用的商品不允许物理删除，可下架。下架商品不允许新加购或新评价。系统没有接入真实支付、物流或库存服务。

## 主要接口与代码

| 功能 | 入口 |
| --- | --- |
| 分类计数 | `GET /api/categories` |
| 商品筛选 | `GET /api/products?page=0&size=12&category=typing&q=keyboard&sort=price-asc` |
| 商品详情 | `GET /api/products/{id}` |
| 快速加购 | `POST /api/cart/items`，JSON 包含 `productId`、`quantity`、`cartFormToken` |
| 评价读取/保存 | `GET/POST /api/products/{id}/reviews` |
| 个人资料 | `GET /account`、`POST /account/profile` |
| 地址列表与表单 | `/account/addresses`、`/account/addresses/new`、`/account/addresses/{id}/edit` |
| 地址写入 | `POST /account/addresses`、`/{id}`、`/{id}/default`、`/{id}/delete` |
| 结账 | `POST /checkout`，表单包含 `checkoutToken` 与 `addressId` |

订单地址快照位于 `entity/ShippingSnapshot.java`，由 `Order` 的 `@Embedded` 字段保存。`CheckoutTransactionService` 在保存订单的同一事务中核对地址归属并复制内容。账户地址由 `ShippingAddressService` 管理；评价由 `ProductReviewService` 管理。

## 运行新版

1. 如果旧服务还在运行，在原启动窗口按 `Ctrl+C` 停止它。
2. 正式持久化：运行 `Start-MySQL.cmd`，输入自己的数据库凭据，启动成功后访问 `http://127.0.0.1:18080/products`。
3. 临时演示：运行 `Start-Demo.cmd`，访问 `http://127.0.0.1:18083/products`。此模式使用内存 H2，停止后数据丢失。
4. 如浏览器仍显示旧界面，使用 `Ctrl+F5` 刷新。无需单独启动 Angular 4200。

启动器优先选择修改时间较新的 target/runtime JAR。修改源码后应先运行前端 `npm run deploy`，再执行 Maven `package`，并更新交付用 runtime JAR。

## 验证范围

本轮后端自动化测试覆盖账户持久化、地址 CRUD 与归属隔离、结账地址快照、防重复下单、分类搜索排序、评价校验及数据库保存；前端测试覆盖独立卡片操作、过滤分页状态、图片对话框、评价回显和语言切换。

HTTP 整合检查使用独立 H2 演示服务；该结果不等同于重新验证用户现有的 MySQL。正式录制前应在 MySQL 模式完成一次“注册/资料编辑 → 地址管理 → 分类浏览/加购 → 结账 → 历史 → 退出再登录”的操作。

2026-10-10 本轮结果：后端 170 项测试、前端 51 项测试、HTTP 流程 35 项检查、Chrome 浏览器流程 21 项检查全部通过。浏览器覆盖桌面及 390px 手机宽度，未发现横向溢出或未捕获的 JavaScript 异常。修复了评价编辑时评分下拉框未正确回显已保存评分的问题。

完整流程检查记录见 [HTTP 验收](store-upgrade/http-results.json) 与 [浏览器验收](store-upgrade/browser-results.json)。页面截图见 [首页](store-upgrade/home-desktop.png)、[账户](store-upgrade/account-desktop.png)、[手机结账](store-upgrade/checkout-mobile.png)。截图中的账号、地址和评论均来自独立演示库中的测试操作。

## 建议演示顺序

1. 首页点击四个分类，展示每类商品；切换中文并搜索商品。
2. 点击图片放大、Escape 关闭；点击“查看详情”展示品牌、发货地和评价。
3. 注册账号，进入个人中心补充资料；保存后退出再登录，展示数据仍然存在。
4. 在地址管理新增两个地址，演示编辑、设为默认和删除。
5. 返回分类目录，通过购物车图标直接加购；结账时选择地址并提交订单。
6. 在订单详情展示商品与地址快照；修改账户中的地址后再次打开旧订单，展示历史记录保持原地址。
7. 发布评价并修改评分；切换中英文，展示语言在商品页、账户、购物车和订单页之间保持一致。

讲解 `Order.java` 时可重点说明：`@Entity` 对应 `orders` 表，`user` 关联购买者，`createdAt` 与 `totalAmount` 记录交易，唯一 `checkoutToken` 防重复下单，`@Embedded ShippingSnapshot` 将下单时的收货信息存入订单，避免后来修改地址影响历史订单。
